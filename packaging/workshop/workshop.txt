version=1
title=Talky - LibertyTalk Live Events
description=Talky connects your stream to your Project Zomboid game. When LibertyTalk receives a follow, a sub, bits, a raid, a channel point redemption or a Super Chat, it calls the Talky bridge, and the mod plays the matching workflow in the game: a zombie named after the new follower, a horde sized by the raid, the helicopter for 1000 bits, a storm, an item for a donation.
description=
description=[h2]What you need[/h2]
description=[list]
description=[*]Project Zomboid Build 42.20.1 or later: single player, hosted game or dedicated server
description=[*]The Talky bridge, from the GitHub releases: https://github.com/Tech-Liberty/talky-project-zomboid/releases (Node.js 18 or later)
description=[*]Single player: the bridge and cloudflared (a public HTTPS address) on your Windows PC
description=[*]Server: the bridge on the machine of the server (Linux or Windows), one TCP port open; the streamers install nothing but the mod
description=[*]A LibertyTalk account with Twitch or YouTube connected, and the "Project Zomboid · Talky" widget
description=[/list]
description=
description=[h2]How it works[/h2]
description=Project Zomboid mods cannot open network connections. The bridge receives the webhooks from LibertyTalk and writes jobs to the Zomboid/Lua folder, and the mod reads them every second. Press F8 in game to open the Talky window: bridge status, webhooks, workflows, game events and settings.
description=This Workshop item contains the mod only. Download the bridge zip from GitHub, extract it to a folder you keep (for example Documents/Talky, not Zomboid/mods) and double-click start-bridge.cmd: on its first start, the bridge creates its configuration and copies its token to the clipboard. Do not copy the Talky folder of the zip to Zomboid/mods: the game would see two mods with the id Talky.
description=
description=[h2]Multiplayer[/h2]
description=Talky must be on the server and on every client. Dedicated server: add Talky to Mods= and the id of this item to WorkshopItems= in the server .ini. Hosted game: add Talky on the Mods and Steam Workshop pages of Host > Manage settings.
description=The admin runs the bridge in server mode on the machine of the server (start-bridge.sh on Linux, start-bridge.cmd server on Windows, or on the PC that hosts the game), opens its port (7420 by default), then adds each streamer in game: F8 > Webhooks. Each streamer gets an address and a token to paste into their LibertyTalk widget; no bridge and no tunnel on their PC. The effects happen around the streamer's character and every player sees them. The calls arrive in clear text (http): put a reverse proxy in front of the bridge for https.
description=The server applies its own limits on the Talky page of the sandbox options: zombies per action and per 10 minutes, one switch per category, cooldowns, distance from other players. Admins and moderators manage Talky; in a hosted game the host is not admin at first: press "Allow me (host)" in F8. Fire and the helicopter are off by default on a server.
description=
description=[h2]Limits[/h2]
description=Single player: the address of a quick Cloudflare tunnel changes at each launch: paste the new one in the widget settings on LibertyTalk. Server: the machine of the server must run Node.js and be reachable on the port of the bridge. Update the mod and the bridge together. Version 0.5.0 was tested against a simulated game API (single player, dedicated server, hosted game); please report on GitHub anything that does not work in a real game.

description=[h2]Fonctionnement[/h2]
description=Les mods de Project Zomboid ne peuvent pas ouvrir de connexion réseau. Le bridge reçoit les webhooks de LibertyTalk et écrit des jobs dans le dossier Zomboid/Lua, que le mod lit chaque seconde. Appuyez sur F8 en jeu pour ouvrir la fenêtre Talky : état du bridge, webhooks, workflows, événements du jeu et réglages.
description=Cet élément du Workshop contient uniquement le mod. Téléchargez le zip du bridge sur GitHub, décompressez-le dans un dossier que vous gardez (par exemple Documents/Talky, pas dans Zomboid/mods) et double-cliquez sur start-bridge.cmd : au premier lancement, le bridge crée sa configuration et copie son jeton dans le presse-papiers. Ne copiez pas le dossier Talky du zip dans Zomboid/mods : le jeu verrait deux mods avec l'id Talky.
description=
description=[h2]Multijoueur[/h2]
description=Talky doit être sur le serveur et sur chaque client. Serveur dédié : ajoutez Talky à Mods= et l'id de cet élément à WorkshopItems= dans le .ini du serveur. Partie hébergée : ajoutez Talky sur les pages Mods et Workshop Steam de Héberger > Modifier les réglages.
description=L'admin lance le bridge en mode serveur sur la machine du serveur (start-bridge.sh sous Linux, start-bridge.cmd server sous Windows, ou sur le PC qui héberge la partie), ouvre son port (7420 par défaut), puis ajoute chaque streamer en jeu : F8 > Webhooks. Chaque streamer reçoit une adresse et un jeton à coller dans son widget LibertyTalk ; ni bridge ni tunnel sur son PC. Les effets se produisent autour du personnage du streamer et tous les joueurs les voient. Les appels arrivent en clair (http) : placez un proxy inverse devant le bridge pour du https.
description=Le serveur applique ses propres limites sur la page Talky des options bac à sable : zombies par action et par 10 minutes, un interrupteur par catégorie, délais, distance des autres joueurs. Les admins et modérateurs gèrent Talky ; en partie hébergée, l'hôte n'est pas admin au départ : cliquez sur « M'autoriser (hôte) » dans F8. Le feu et l'hélicoptère sont désactivés par défaut sur un serveur.
description=
description=[h2]Limites[/h2]
description=Solo : l'adresse d'un tunnel Cloudflare rapide change à chaque lancement : collez la nouvelle dans les réglages du widget sur LibertyTalk. Serveur : la machine du serveur doit faire tourner Node.js et être joignable sur le port du bridge. Mettez à jour le mod et le bridge ensemble. La version 0.5.0 a été testée sur une API du jeu simulée (solo, serveur dédié, partie hébergée) ; signalez sur GitHub ce qui ne fonctionne pas en partie réelle.
